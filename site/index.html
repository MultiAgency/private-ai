Private Investigator

AI code review that proves your code stayed private. Your code is read only inside hardware enclaves that prove what they run, and every review comes with a receipt anyone can check.

Install on GitHub Run it as an Action How it works

You're set. Nothing runs until a pull request asks: open one, mark one ready for review, or comment /review on an open one. The Private Investigator check appears on it within seconds, and the review lands a few minutes later, with its receipt.

Two ways to run it

The same review and the same receipts, run where you prefer.

  • The GitHub App

    Install it and pick the repositories: nothing else to set up. It reviews a pull request when it opens or leaves draft; later pushes, when someone with write access comments /review or presses Re-run, and until then the new commit's check says it isn't reviewed. Your code is fetched and read only inside an attested OutLayer enclave, running our published build. Free for 10 reviews per installation a month, from a shared monthly pool: each check says how many are left, and when either runs out, the check says so and reviews resume on the 1st.

How it works

Three checks between your code and the model, then a receipt.

  1. Attest

    Before any code is sent, check NEAR AI Cloud's evidence for a fresh nonce: Intel's signed quote for the model's machine, fully patched, and NVIDIA's signed verdict on its GPUs.

  2. Encrypt

    Encrypt every request, tool calls included, to the key that evidence binds. Only the attested enclave can read your code; the gateway in front of it sees ciphertext.

  3. Sign

    The enclave signs each reply over the exact request and response bytes, and a reply is used only once its signature checks out.

  4. Receipt

    The evidence and signatures form a receipt, saved with the run. It holds hashes, not code, so anyone can check it.

With the Action, these steps run on your runner. With the App, they run inside an attested OutLayer enclave that fetches your code from GitHub itself, and the receipt adds each step's attestation, naming the exact build that read your code. Either way no MultiAgency server sees your code, and the source is public.

What the App's operators can see

        
Never your code or its review. This much, and no more:

      

      
    
        
  • Event notices
    GitHub sends its notices of pull request events (titles, descriptions, who pushed) to our relay, which forwards only ids to the enclave, and holds those only while a review runs. Its source is public.
    • 
        
  • Public receipts
    Each review's receipt is published in OutLayer's public storage: hashes, signatures, attestations, its count of new findings, and a commitment to the pull request that only the review's link opens. Never your repository's name, code or review.
    • 
        
  • Counts and timing
    How many reviews each installation runs (for the free tier), and when. OutLayer sees when each step runs and how large its requests are.
    • 
      

    


    

      

        
What it doesn't prove

        
Where the guarantees stop, so you can decide what else to check.

      

      
    
        
  • What happens on your runner
    The Action runs there. Read its source, pinned by commit in your workflow.
    • 
        
  • That a build is its source
    The App's receipt names the build that read your code. Every release is recorded with its commit in app/builds.json, and rebuilds bit for bit from it (CI checks this); rebuilding it yourself is the step that closes the loop.
    • 
        
  • The enclaves' platforms
    The proofs rest on Intel TDX and NVIDIA confidential computing, and for the App on OutLayer's keystore and its approved worker builds.
    • 
        
  • Which model instance answered
    Instances share one signing key, so a signature proves that an attested enclave answered, not which one.
    • 
        
  • What NEAR's images do
    The receipt records the compose hashes, and NEAR publishes the files they measure. Auditing those images is a separate step.
    • 
        
  • That the review is right
    The proof covers where your code was read, not the quality of the findings. Measured on a real pull request, the private model missed two regressions in money paths that span files, which a frontier model caught (the evaluation). Use it as a second reviewer, not as the sign-off on payment or permission code.
